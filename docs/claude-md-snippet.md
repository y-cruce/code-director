Append the block below to `~/.claude/CLAUDE.md` (applies to all projects) or to a project's `CLAUDE.md`. Skills load only when triggered, so the routing rule must live in `CLAUDE.md` to guarantee every matching task takes this path.

```markdown
## An agent is the executor

For any task that reads code to understand it, debugs, implements a change, or reviews a diff, load the `code-director` skill and dispatch the work. Write the brief, judge the result, make the calls; do not do the work yourself.

Give each task to one executor from start to finish, chosen by where the difficulty lies. When the hard part is finding a cause (a bug, an unknown root cause), send the whole task to Codex (`EXECUTOR: codex`). When it is design or implementation, send it to Antigravity (`agy`, alias of `antigravity`), whose default model, gemini-pro-orchestrator-neon, is strong at complex coding tasks and frontend work; all frontend work, including bugs, verification, reviews and small changes, goes to agy. Use the other executors in parallel: read-only auxiliary investigations, competing plans from Codex and agy whenever a plan or design is needed, and reviews. For frontend reviews use `MODE: investigate` with a read-only review brief. Follow the `code-director` skill's ACP fallback when the installed tool schema lacks the agy names.

Send corrections to a running task with `mcp__codex__message`, omitting `delivery` or setting `delivery: "steer"`. Codex, Qoder, and DSH with its steering extension support input in the same job/thread/turn when the plugin reports `midTurnSteer: true`; ACP alone is no reason to queue. agy accepts steer while its prompt is active, including while commands run; the driver refuses it only while waiting for background commands after an early `end_turn`, so use queue or interrupt then, and say whether to stop its background commands. Use `delivery: "queue"` for an intended next turn, and `delivery: "interrupt"` when the current turn must stop immediately. If steering is unavailable or the turn has ended, check status and choose the next action by intent; use `continue` for a finished job. Submission or acceptance does not prove model execution.

Reviews and second opinions go to Codex (`EXECUTOR: codex`). When the user picks qodercli (`EXECUTOR: qoder`), choose its model by complexity. Work whose shape is already settled -- a scoped change, a question answered by reading a known area -- runs on its default model, which is fast and cheap enough to run many at once. Medium-complexity work, more than the default should carry, uses `MODEL: performance` (GPT-5.6-sol, 1M context). Only high-complexity work -- deciding the approach or the architecture, and the implementation that follows from it -- uses `MODEL: ultimate` (Opus 5).
```
